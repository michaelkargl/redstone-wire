## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After all three block types (Input, Output, Connector) are created and working, add the instanceof filter to RedstoneInputBlock.neighborChanged() that prevents feedback loops.

Without this filter, two problems occur:
1. **Phantom sustained signals**: When applySignalToNetwork() updates an OutputBlock's POWER via level.setBlock(..., 3), it triggers neighborChanged() on adjacent InputBlocks. On the next periodic tick, computeNetworkInputPower() could read the OutputBlock's getSignal() emission as external input, sustaining the signal indefinitely after the source is removed.
2. **Cross-network cascading**: The isUpdating flag is per-entity, so OutputBlock in network A adjacent to InputBlock in network B triggers unnecessary recalculations.

The fix: In neighborChanged(), skip the call to entity.updateSignalInNetwork() when the neighbor is instanceof AbstractRedstoneChainBlock. Also ensure getPowerFromDirection() in RedstoneChainEntity filters out AbstractRedstoneChainBlock instances.

See requirements-neighborchanged-feedback-loop-analysis.md for the full investigation.
